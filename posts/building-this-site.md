一开始其实没想太多，就想要一个自己的地盘：能写文章、能放项目、能贴点照片，同时自己看得顺眼。挑了半天，最后决定用 Flutter 来写。

## 为什么是 Flutter

我对 Flutter 比较熟，而且它一套代码能同时出网页版和桌面版，换来换去不用重写。加上 Material 3 的主题切得好看 —— 浅色深色、圆角、配色这些，搭起来省很多事。

不过也要承认，用 Flutter 写网站多少有点"重"。首屏要加载一段引擎，跟纯静态的 HTML 站比，肯定没那么轻。权衡下来我还是选了它，毕竟更熟悉，改动也更快。

## 内容用 Markdown 管

这是最开始就定好的：所有内容都是 `.md` 文件，用 YAML 在文件头写标题、日期、标签这些元信息。原因很简单——

- 想改一段话，用任何编辑器打开就能改，不用进后台
- 跟着 Git 走，每次改动都有记录
- 想换平台，把目录整个拷走就行，数据不锁在某个系统里

程序做的事情其实很朴素：扫目录、读文件、按模板渲染出来。真正花时间的地方在后面。

## 顺手做的几件事

- 深色浅色主题切换，切换时从点击的地方向四周扩散，像一层水波推开旧的画面。
- 背景是一层淡淡的网格，鼠标扫过时有一圈跟手的光晕，纯装饰，不挡内容。
- 技能和照片的展示都重做了一遍，不再是一坨文本。

## 踩过的坑

- **CSS 没用上，全部交给 Flutter 的布局**，看似省心，但要调出"干净"的质感反而更花时间，留白、字号、行高都要自己抠。
- **内容目录的打包**：Flutter 只打包你在 `pubspec` 里声明过的资產目录。加新目录忘了登记，就会在线上"文件不存在"。
- **字体**：中文系统字体包太大，只能做子集，挑了几个常用字，剩下的让浏览器自行替换。

## 大概就是这样

网站本身不复杂，复杂的是想让它"看着舒服"。如果你也想把内容用 Markdown 管起来，可以翻一下站里的其他文章，或者直接看看我的代码。
